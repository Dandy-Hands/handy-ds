import { Field, Fieldset, Form } from 'handy-ds';

# Field

One labelled form value: label, control, description, and error, wired together
for assistive tech. `Fieldset` groups related fields. `Form` validates and
submits. For a text input without a Field wrapper, use `TextInput`.

<Field.Root>
  <Field.Label>Email</Field.Label>
  <Field.Control placeholder="you@example.com" />
</Field.Root>

## Usage

Use the full Field set for any labelled text entry: `Field.Root` wraps one
value, and the label, description and error attach to the control
automatically. Do not use a bare `TextInput` when a visible label exists — use
`Field.Control`, which renders the same input with the wiring included. Use
a bare `TextInput` only when the control has no visible label, and give it an
`aria-label`.

## Base UI API

Wraps Base UI's `Field`, `Fieldset`, and `Form`; every part passes
through unchanged, styled via `part()`.

| Element | Notes |
| ------- | ----- |
| `Field.Root/Label/Control/Description/Error/Item` | All exposed, namespace mirrored; each renders its own DOM. |
| `Fieldset.Root/Legend` | Exposed, namespace mirrored. |
| `Form` | Single `part()`; validation and submit behavior are Base UI's, untouched. |
| `Field.Root`'s `invalid` and Base UI's `data-invalid` | Consumed by CSS for the error state. |
| Callback-form `className`/`style` | Available via passthrough, not documented. |

## Extension API

### Field.Root

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `invalid` | `boolean` | — | Marks the field and its control, description and error with `data-invalid`. |
| `children` | `ReactNode` | — | Label, control, description and error content. |

### Field.Error

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `match` | `boolean \| ValidityState key` | — | Shows the error when the control's validity matches. `valueMissing` — empty required field. `typeMismatch` — wrong format, e.g. an email. `true` — always show. |

### Form

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `onSubmit` | `(event: FormEvent) => void` | — | Fires when the form submits. |

`render`, standard attributes, and every remaining Base UI prop are passthrough — they appear here only, never get their own section.

## Size

The size axis on `Field.Control`. It sets height, padding, radius, and border
width from `hds/sem/measure/space/*`, `hds/sem/measure/size/*`, `hds/sem/radius/control`, `hds/sem/border/control`. `Field.Control` defaults to
`1000`. Give it `data-size` to match a neighbouring control. `TextInput` has
its own page, `text-input`, with the same axis as the `size` prop.

### data-size="800"

<Field.Control data-size="800" placeholder="Compact control" />

### data-size="1000"

<Field.Control placeholder="Default control" />

### data-size="1200"

<Field.Control data-size="1200" placeholder="Large control" />

## Invalid

`invalid` on `Field.Root` drives the error look: the control takes the error
border and colors, and `Field.Error` shows its message when the validity
matches.

<Field.Root invalid>
  <Field.Label>Email</Field.Label>
  <Field.Control defaultValue="not-an-email" />
  <Field.Error match>Enter a valid email.</Field.Error>
</Field.Root>

## Description and error

`Field.Description` renders caption type below the control. `Field.Error`
renders in the danger feedback color and is read out with the control.

<Form onSubmit={(e) => e.preventDefault()}>
  <Field.Root>
    <Field.Label>Name</Field.Label>
    <Field.Control placeholder="Jane Doe" />
    <Field.Description>As it appears on your ID.</Field.Description>
  </Field.Root>
</Form>

## Fieldset and Form

`Fieldset.Root` groups related fields under a `Fieldset.Legend`. `Form` wires
validation and submit. Their gaps borrow Input/Field measure tokens, so they
scale with density.

<Form onSubmit={(e) => e.preventDefault()}>
  <Fieldset.Root>
    <Fieldset.Legend>Payment</Fieldset.Legend>
    <Field.Root><Field.Label>Name on card</Field.Label><Field.Control /></Field.Root>
  </Fieldset.Root>
</Form>

## Anatomy

| Part | Semantic token |
| ---- | -------------- |
| Control background, text, border | `hds/sem/color/field/{default,hover,error,disabled}/*` |
| Control size (height, padding, radius, border) | `hds/sem/measure/space/*`, `hds/sem/measure/size/*`, `hds/sem/radius/control`, `hds/sem/border/control` |
| Group focus ring | `hds/sem/color/focus/ring`, `hds/sem/border/focus` |
| Label | `hds/sem/color/content/default/fg`, `hds/sem/typography/label/*` |
| Description | `hds/sem/color/content/muted/fg`, `hds/sem/typography/caption/*` |
| Error text | `hds/sem/color/feedback/danger/fg` |
| Field gap / Form gap | `hds/sem/measure/space/*`, `hds/sem/measure/size/*`, `hds/sem/radius/control`, `hds/sem/border/control` |

## Owner notes

- Base UI mapping: wraps `@base-ui/react/field`, `field/set`, and
  `form`; namespaces are mirrored so the underlying docs apply part for part.
  Every part passes props through, `render` included.
- Extension decisions: `Field.Control` takes `data-size` (`800`, `1000`, `1200`) so the part
  stays prop-free. No extension props on `Field`, `Fieldset`, or `Form`.
- Known constraints: layout gaps borrow Input/Field measure tokens because the
  spec has no layout-spacing tokens yet (gap 13, needs review). Error text
  contrast is checked in the default context only — forms inside colored
  sections need a `data-context="default"` container (gap 14, needs review).
- Accessibility: label, description, and error are wired to the control by the
  underlying Field behavior. Error text uses the danger feedback color, which
  is contrast-checked in the default context.
