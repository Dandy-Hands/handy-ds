import { useState } from 'react';
import { AlertDialog, Button, Dialog } from 'handy-ds';

export function DialogDemo() {
  const [open, setOpen] = useState(false);
  return (
    <>
      <Button onClick={() => setOpen(true)}>Open dialog</Button>
      <Dialog open={open} onOpenChange={setOpen} title="Edit profile"
        actions={<Button onClick={() => setOpen(false)}>Done</Button>}>
        Changes apply to every workspace.
      </Dialog>
    </>
  );
}

export function AlertDialogDemo() {
  const [open, setOpen] = useState(false);
  return (
    <>
      <Button variant="danger" onClick={() => setOpen(true)}>Delete project</Button>
      <AlertDialog open={open} onOpenChange={setOpen} title="Delete project?"
        description="This removes it for everyone." confirm="Delete" variant="danger" onConfirm={() => setOpen(false)} />
    </>
  );
}

# Dialog

A task that blocks the page. The popup is a surface at elevation 3; a dimmed
backdrop covers the page; focus stays inside until the dialog closes.
`AlertDialog` is the confirm/cancel variant and cannot be dismissed by clicking
outside.

<DialogDemo />

## Usage

Use Dialog when the user must finish or dismiss before carrying on: edit
forms, blocking choices. Use AlertDialog to confirm destructive actions —
deletion, permission changes. Do not use Dialog for extra detail next to a
trigger — use Popover.

## Base UI API

Wraps Base UI's `Dialog` and `AlertDialog`; every part passes through
unchanged, styled via `part()`. Both keep Base UI's modal defaults
(`modal: true`).

| Element | Notes |
| ------- | ----- |
| `Root` props (`open`, `defaultOpen`, `onOpenChange`, `modal`, ...) | Exposed — full passthrough. |
| `Trigger`, `Close` | Styled as Action buttons (secondary look; `data-priority` overrides). |
| `Portal`, `Backdrop` | Portal passthrough; backdrop gets the Overlay scrim. |
| `Popup` | Surface elevation 3, popup transitions, centered modal layout. |
| `Title`, `Description` | Heading type / body color. |
| `initialFocus` / `finalFocus` (Popup) | Exposed — passthrough. |
| `data-open`, `data-starting-style`, `data-ending-style` | Consumed by CSS for popup/backdrop transitions. |
| Callback-form `className`/`style` | Available via passthrough, not documented. |

`AlertDialog` mirrors every decision; the difference is the dismissal rules (no outside-click dismiss).

## Extension API

### Dialog.Root

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `open` / `defaultOpen` | `boolean` | — | The controlled / initial open state. |
| `onOpenChange` | `(open, eventDetails) => void` | — | Fires when the dialog opens or closes. |
| `modal` | `boolean \| 'trap-focus'` | `true` | `true` traps focus, locks page scroll, and dismisses on outside press (AlertDialog never dismisses on outside press). `'trap-focus'` traps focus without locking scroll. |
| `children` | `ReactNode` | — | Part content: backdrop, popup, title, description, close. |

### Dialog.Trigger, Dialog.Close

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `data-priority` | `'primary' \| 'secondary' \| 'tertiary'` | `'secondary'` | Visual weight of the trigger and close buttons. |

`initialFocus`/`finalFocus` (Popup), `render`, and standard attributes are passthrough — they appear here only, never get their own section.

## Open state

The trigger opens the dialog; the backdrop dims the page with the Overlay
token; Escape and the close button dismiss.

## Alert dialog

`AlertDialog` blocks outside-click dismissal, so a destructive confirm always
gets an explicit choice. Its trigger and close carry the same button look.

## Owner notes

- Base UI mapping: wraps `@base-ui/react/dialog` and `alert-dialog` in one
  family; both namespaces are mirrored, and every prop passes through. The
  popup, backdrop, and text parts are styled; Portal is a passthrough.
- Extension decisions: no extension props. Elevation is fixed at 3 and the
  popup width is structural (`min(32rem, calc(100vw - 2rem))`). Trigger and
  Close carry the secondary Button look, changeable with `data-priority`.
- Known constraints: the decisions log ("Triggers carry no styling") and the
  shipped trigger styling disagree — this spec follows the code; reconcile one
  side at review. The popup is centered and scrolls internally at small
  viewport heights.
- Accessibility: focus is trapped and restored by the underlying behavior;
  `Title` labels the dialog. Give AlertDialog an explicit cancel and confirm.
