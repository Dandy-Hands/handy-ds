import { useState } from 'react';
import { Button, Dialog, Field, Inline, Text, TextInput } from 'handy-ds';

export function DialogDemo({ label, withActions = true, body, ...props }) {
  const [open, setOpen] = useState(false);
  return (
    <>
      <Button variant="secondary" onClick={() => setOpen(true)}>{label}</Button>
      <Dialog
        open={open}
        onOpenChange={setOpen}
        title="Edit profile"
        actions={withActions ? (
          <>
            <Button variant="secondary" onClick={() => setOpen(false)}>Cancel</Button>
            <Button onClick={() => setOpen(false)}>Save</Button>
          </>
        ) : undefined}
        {...props}
      >
        {body ?? (
          <Field.Root>
            <Field.Label>Name</Field.Label>
            <TextInput />
          </Field.Root>
        )}
      </Dialog>
    </>
  );
}

# Dialog

Dialog is a box over the page for a short task. The user finishes or dismisses the task
before going back to the page. Dialog is one component with props and children. It has a
header row with the title and an X button, a body that scrolls, and an optional button row.
Code opens and closes it through `open` and `onOpenChange`. A normal Button opens it.

<DialogDemo label="Edit profile" />

## Usage

Use Dialog for a short task that blocks the page: edit a record, fill a small form, or read a
required notice. Keep the open state in code: `const [open, setOpen] = useState(false)`, a
Button with `onClick={() => setOpen(true)}`, and `<Dialog open={open} onOpenChange={setOpen}>`.

Do not use Dialog to confirm a destructive action. Use AlertDialog. Do not use it for longer
content where the page context helps. Use Drawer. Do not use it for a small panel that leaves
the page usable. Use Popover. Do not put a long flow of several steps in a Dialog. Use a page.

## Base UI API

Dialog wraps `@base-ui/react/dialog`. The parts are internal. None is exported.

| Element | Notes |
| ------- | ----- |
| `Root` `open`, `onOpenChange` | Exposed and required. The only way to open and close the dialog. |
| `Root` `disablePointerDismissal` | Exposed, Base UI name. |
| `Root` `defaultOpen`, `modal`, `onOpenChangeComplete`, `actionsRef`, `handle`, trigger IDs | Omitted. `modal` is fixed `true`. |
| `Trigger` | Omitted. A normal Button with `onClick` opens the dialog. |
| `Portal`, `Backdrop`, `Viewport`, `Popup` | Rendered inside. The scrim is always rendered. |
| `Popup` `initialFocus`, `finalFocus` | Omitted. Base UI default focus. |
| `Title` | Rendered from `title`. |
| `Description` | Omitted. |
| `Close` | The X button only. |
| `render`, `className`, `style` | Omitted. |
| `data-open`, `data-starting-style`, `data-ending-style`, `data-nested` | Read by CSS for the transition and for a dialog on top of another dialog. |

## Extension API

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `open` | `boolean` | required | Whether the dialog is open. Keep it in state. |
| `onOpenChange` | `(open: boolean) => void` | required | Called when the user closes the dialog with the X button, `Escape`, or a click outside. |
| `title` | `ReactNode` | required | The heading in the header row. Screen readers read it as the dialog name. |
| `width` | `'8000' \| '9600' \| '12800' \| 'full'` | `'9600'` | Width of the box. `full` fills the screen minus a small gap. |
| `actions` | `ReactNode` | — | The button row at the bottom. Put the main action last. Absent: no row. |
| `disablePointerDismissal` | `boolean` | `false` | With `true`, a click outside does not close the dialog. |
| `children` | `ReactNode` | — | The body. It scrolls when the dialog is taller than the screen. |

## Width

`width` sets the width of the box. `8000`, `9600`, and `12800` read `measure/width/{step}`.
`full` fills the screen minus the side gap, in width and in height. Every width shrinks to fit
a small screen.

## Actions

`actions` is the button row at the bottom, aligned to the end. The row stays visible while the
body scrolls. Without `actions`, the dialog has no button row. The X button is always there.

<Inline gap="200">
  <DialogDemo label="With actions" />
  <DialogDemo label="Without actions" withActions={false} body={<Text>Your changes are saved.</Text>} />
  <DialogDemo
    label="Long body"
    body={<Text>{'This body is longer than the screen. Only the body scrolls. The header row and the button row stay visible. '.repeat(40)}</Text>}
  />
</Inline>

## Owner notes

- Base UI mapping: `Root`, `Portal`, `Backdrop`, `Viewport`, `Popup`, `Title`, and `Close`
  from `@base-ui/react/dialog`, all inside `<Dialog>`.
- Extension decisions: one component with `title` and `actions` props (overlay exception in
  `docs/api-conventions.md` section 1). No trigger: `open` and `onOpenChange` are the one way
  to open and close it. The X is a tertiary Button, size `800`, and is always shown.
- Known constraints: the dialog renders at the end of the page. It uses the page colors and
  mode. A `data-context`, `data-mode`, or `data-section` on an ancestor does not reach it. On a
  phone the box shrinks to the screen width; there is no automatic full screen.
- Accessibility: focus moves into the dialog on open and stays inside. Focus goes back to the
  element that had it before on close. The title names the dialog. `Escape` closes it.
