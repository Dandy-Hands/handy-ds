import { Card, Stack, Text } from 'handy-ds';

# Card

A box of related content: background, border, shadow, rounded corners, and
padding at a chosen elevation. A card whose element is a link or a button is
clickable as a whole and shows a hover border. Renders a `div` by default.

<Card>
  <Stack gap="200">
    <Text variant="headline" render={<h3 />}>Pro plan</Text>
    <Text>Everything in Free, plus team seats.</Text>
  </Stack>
</Card>

## Usage

Use Card to group content that belongs together: a settings block, a product
summary, a project card, a dashboard tile. Pick the lowest elevation that
separates the card from its ground; `base` is the flat, outlined card. Do not
use it for spacing alone (use Stack or Grid) or for a full-width page band
(use Section). Do not put a second link or a button inside a card that is a
link.

## Base UI API

No Base UI primitive — a single-part `useRender` component that passes all
standard attributes through.

| Element | Notes |
| ------- | ----- |
| `render` | Exposed — swap the element (`<article />`, `<li />`, `<a />`, a router link) without changing the look. A link or button element turns on the hover border. |
| Native `div` props (`id`, `aria-*`, `className`, ...) | Exposed — full passthrough. `style` is not part of the type. |
| Callback-form `className` | Available via passthrough, not documented. |

## Extension API

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `elevation` | `"base" \| "raised" \| "floating" \| "modal"` | `"raised"` | Distance above the page. `"base"` — flat with a border, no shadow (the outlined card). `"raised"` — the normal card. `"floating"` — over other content. `"modal"` — the topmost level. |
| `padding` | `"none" \| "200" \| "300" \| "400" \| "600" \| "800" \| "1000" \| "1200"`, or an object keyed by breakpoint | `"600"` | Space between the edge and the content. `"none"` lets a photo run to the edge. Keys: `base` (required), `sm`, `md`, `lg`, `xl`. |
| `children` | `ReactNode` | — | Card content. |

`render` and standard attributes are passthrough — they appear here only, never get their own section.

## Elevation

The elevation axis picks the surface level: background, border, and shadow
change together.

### elevation="base"

Flat on the page with a border and no shadow. This is the outlined card.

<Card elevation="base"><Text>Base</Text></Card>

### elevation="raised"

The default card.

<Card elevation="raised"><Text>Raised</Text></Card>

### elevation="floating"

A card over other content.

<Card elevation="floating"><Text>Floating</Text></Card>

### elevation="modal"

The topmost level. Dialogs use this level.

<Card elevation="modal"><Text>Modal</Text></Card>

## Padding

The padding prop sets the space between the card edge and its content. It
takes a space step or `"none"`.

### padding="none"

For a photo that runs to the card edge. Put padding back around the text with
a nested element.

<Card padding="none"><Text>No padding</Text></Card>

### padding="200"

<Card padding="200"><Text>200</Text></Card>

### padding="300"

<Card padding="300"><Text>300</Text></Card>

### padding="400"

A small dashboard tile.

<Card padding="400"><Text>400</Text></Card>

### padding="600"

The default.

<Card padding="600"><Text>600</Text></Card>

### padding="800"

### padding="1000"

## Link card

Give the card a link element with `render` to make the whole card clickable.
Its border changes color on hover, and it shows the focus ring when it gets
keyboard focus. A `<button>` element works the same way. Other elements have
no hover.

<Card elevation="base" render={<a href="#link-card" />}>
  <Stack gap="200">
    <Text variant="headline" render={<h3 />}>Kitchen remodel</Text>
    <Text>New cabinets, counters, and lighting.</Text>
  </Stack>
</Card>

## Inside a colored section

Inside a colored section a card is a darker brand panel. Put
`data-context="default"` on the card for the normal light look, for example
around a form.

<section data-section="hero">
  <Stack gap="400">
    <Card><Text>A brand panel.</Text></Card>
    <Card data-context="default"><Text>Normal colors, restored.</Text></Card>
  </Stack>
</section>

## Anatomy

| Part | Semantic token |
| ---- | -------------- |
| Ground (per elevation) | `hds/sem/color/surface/{base,raised,floating,modal}/bg` |
| Border color (per elevation) | `hds/sem/color/surface/{base,raised,floating,modal}/border` |
| Border color on hover (link or button card) | `hds/sem/color/surface/hover/border` |
| Shadow | `hds/sem/elevation/{raised,floating,modal}`; `base` has none |
| Border width, radius | `hds/sem/border/container`, `hds/sem/radius/container` |
| Padding | `hds/sem/measure/space/{padding}` (`none` is 0) |
| Content text color | `hds/sem/color/content/default/fg` |
| Hover transition | `hds/sem/motion/control/{duration,easing}` |

## Owner notes

- Base UI mapping: no Base UI primitive — a single-part `useRender` component
  with the same `render` semantics as Base UI parts.
- Extension decisions (re-interview 2026-11-23): `elevation` takes the named
  surface levels (default `raised`; `sunken` is not allowed). `padding` is a
  responsive space step (default `600`). There is no `variant="outline"`:
  `elevation="base"` is the outlined card. There is no `interactive` prop: a
  link or button element turns on the hover border.
- Known constraints: inside a colored section the card stays a brand panel.
  An always-reset behavior was considered and rejected; `data-context="default"`
  is the reset.
- Accessibility: a link card uses its whole text as the link name, so keep its
  content short and do not nest other links or buttons in it. A plain card is a
  container with no role; give it a heading inside when it stands alone.
