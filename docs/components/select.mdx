# Select

Picks one value from a known list that is too long for radio buttons and does
not need typed filtering. The trigger is a standard input-height control; the
options open in an elevated popup list.


<Select.Root items={['Apple', 'Banana', 'Cherry']} defaultValue="Banana">
  <Select.Trigger>
    <Select.Value />
    <Select.Icon />
  </Select.Trigger>
  <Select.Portal>
    <Select.Positioner>
      <Select.Popup>
        <Select.List>
          {['Apple', 'Banana', 'Cherry'].map((f) => (
            <Select.Item key={f} value={f}>
              <Select.ItemText>{f}</Select.ItemText>
              <Select.ItemIndicator />
            </Select.Item>
          ))}
        </Select.List>
      </Select.Popup>
    </Select.Positioner>
  </Select.Portal>
</Select.Root>

## Usage

Use Select when the option list is fixed, longer than about five, and does not
need filtering. Do not use it when the user must type to narrow the list — use
Combobox; do not use it for short lists — use Radio.

## Base UI API

Wraps Base UI's `Select` as a compound component: every part spreads
unchanged, DOM-rendering parts restyled via `part()`. All Base UI props keep
their documented semantics; types like `Select.Root.Props` stay importable
from `@base-ui/react/select`.

| Element | Notes |
| ------- | ----- |
| `Root` props (`items`, `value`, `onValueChange`, `multiple`, `name`, `disabled`, `required`, ...) | Exposed — full passthrough. |
| `Trigger`, `Icon` | Input/Field control with built-in chevron. |
| `Positioner` / `Popup` / `List` / `Item` / `ItemIndicator` | Elevated popup, Action tertiary list items with built-in check. |
| `Label` / `GroupLabel` | Field-label / list-label looks. |
| `Separator`, `Backdrop` | Shared divider and overlay looks. |
| Passthrough-only parts (`Root`, `Value`, `ItemText`, `Group`, `Portal`, scroll arrows) | No styled DOM; every prop passes through, `ref` included. |

## Extension API

Select is a compound component: `Select.Root` takes the configuration props
and the other parts compose the widget.

### Select.Root

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `items` | `Array<string \| { label, value }>` | — | The option list the popup renders. |
| `value` / `defaultValue` | `any` | — | Controlled selected value / uncontrolled initial value. |
| `onValueChange` | `(value, event) => void` | — | Fires when the user picks an option. |
| `multiple` | `boolean` | `false` | Allows several selected values. |
| `name` | `string` | — | Form field name for native submission. |
| `disabled` | `boolean` | `false` | Makes the whole widget inert. |
| `required` | `boolean` | `false` | Marks the field required for forms. |

### Select.Trigger

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `data-size` | `'800' \| '1000' \| '1200'` | `'1000'` | Trigger control size. `800` — dense layouts. `1000` — default. `1200` — large form contexts. |

`render`, `ref`, and standard attributes are passthrough on every part — they appear here only, never get their own section.

## Parts

A Select needs the Root plus a trigger chain and an option list. `Select.Label`
is optional; `Select.ItemIndicator` shows the check on the chosen option.

<Select.Root items={['Apple', 'Banana', 'Cherry']} defaultValue="Banana">
  <Select.Label>Fruit</Select.Label>
  <Select.Trigger>
    <Select.Value />
    <Select.Icon />
  </Select.Trigger>
  <Select.Portal>
    <Select.Positioner>
      <Select.Popup>
        <Select.List>
          {['Apple', 'Banana', 'Cherry'].map((f) => (

              <Select.ItemIndicator />
            </Select.Item>
          ))}
        </Select.List>

</Select.Root>

## Trigger size

The trigger reads the Input/Field control look. `data-size` picks the control
height and padding. Items always read the md action measure; only the trigger
changes size.

## Owner notes

- Base UI mapping: wraps the Base UI Select as a compound component — every
  part and hook spreads through unchanged; types like `Select.Root.Props` come
  from Base UI. Only DOM-rendering parts get classes via `part()`.
- Extension decisions: deliberately none — "no handy-ds props" is the
  components.md contract. Visual overrides go through part props (e.g.
  `data-size="1200"` on the Trigger), which `part()` defaults allow.
- Known constraints: the trigger pins the Input/Field category and items pin
  Action md; the Action size axis is Button-only by decision. Long lists get
  Base UI's scroll arrows, which render unstyled structural parts.
- Accessibility: Base UI provides the listbox semantics, keyboard navigation
  (`Arrow` keys, type-ahead, `Enter`/`Esc`), and `aria-*` wiring. The check
  indicator is decorative; selection is announced by the listbox state. The
  focus ring comes from the shared `:focus-visible` rule.
