import { useState } from 'react';
import { AlertDialog, Button, Inline } from 'handy-ds';

export function AlertDemo({ label, variant, ...props }) {
  const [open, setOpen] = useState(false);
  return (
    <>
      <Button variant={variant === 'danger' ? 'danger' : 'secondary'} onClick={() => setOpen(true)}>{label}</Button>
      <AlertDialog
        open={open}
        onOpenChange={setOpen}
        variant={variant}
        onConfirm={() => setOpen(false)}
        {...props}
      />
    </>
  );
}

# AlertDialog

AlertDialog asks the user one question about an action and waits for an answer, such as
"Delete 3 files?". It is one component with props only. It blocks the page and does not close
on a click outside. It draws its own two buttons: a cancel button that gets focus first, and a
confirm button. Screen readers read the title and the description at once.

<AlertDemo label="Delete files" variant="danger" title="Delete 3 files?" description="You cannot undo this." confirm="Delete" />

## Usage

Use AlertDialog to confirm an action that is destructive or cannot be undone: delete, discard
changes, or cancel a subscription. Write the result in `description`, such as "You cannot undo
this." Name the confirm button with the action, such as "Delete", not "OK".

Do not use AlertDialog for a task with fields. Use Dialog. Do not use it for a message that
needs no answer. Use Toast or Alert.

## Base UI API

AlertDialog wraps `@base-ui/react/alert-dialog`. The parts are internal. None is exported.

| Element | Notes |
| ------- | ----- |
| `Root` `open`, `onOpenChange` | Exposed and required. The only way to open and close the dialog. |
| `Root` `defaultOpen`, `onOpenChangeComplete`, `actionsRef`, `handle`, trigger IDs | Omitted. |
| `Trigger` | Omitted. A normal Button with `onClick` opens it. |
| `Portal`, `Backdrop`, `Viewport`, `Popup` | Rendered inside. The scrim is always rendered. |
| `Popup` `initialFocus` | Fixed to the cancel button. |
| `Popup` `finalFocus` | Omitted. Focus goes back to the element that had it before. |
| `Title`, `Description` | Rendered from `title` and `description`. |
| `Close` | Renders the cancel button. |
| Outside click | Does not close the dialog. |
| `Escape` | Closes the dialog through `onOpenChange(false)`, as cancel does. |
| `render`, `className`, `style` | Omitted. |

## Extension API

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `open` | `boolean` | required | Whether the dialog is open. Keep it in state. |
| `onOpenChange` | `(open: boolean) => void` | required | Called with `false` on cancel or `Escape`. |
| `title` | `ReactNode` | required | The question. Screen readers read it as the dialog name. |
| `description` | `ReactNode` | required | The result of the action. Screen readers read it with the title. |
| `confirm` | `ReactNode` | required | The text of the confirm button. Name the action. |
| `onConfirm` | `() => void` | required | Called on a click of the confirm button. The dialog stays open until `open` is `false`. |
| `cancel` | `ReactNode` | `'Cancel'` | The text of the cancel button. This button gets focus on open. |
| `variant` | `'primary' \| 'danger'` | `'primary'` | The look of the confirm button. |

## Variant

`variant` sets the look of the confirm button. `primary` is for a normal action. `danger` is
for an action that deletes or destroys something. The cancel button is always `secondary`.

## Owner notes

- Base UI mapping: `Root`, `Portal`, `Backdrop`, `Viewport`, `Popup`, `Title`, `Description`,
  and `Close` from `@base-ui/react/alert-dialog`, all inside `<AlertDialog>`.
- Extension decisions: props only. `description` is required, so no confirm is a bare "Are you
  sure?". The width is fixed at `measure/width/9600`. There is no X button. The buttons are
  Button size `1000`; cancel first, confirm last.
- Known constraints: `onConfirm` does not close the dialog. The caller sets `open` to `false`,
  for example after an async delete. The dialog uses the page colors and mode.
- Accessibility: the cancel button gets focus on open. Focus stays inside. `Escape` cancels.
  The title and the description are read at once.
